The gearbox bus

The SMG2 has its own CAN bus to the DME, separate from the car's. On an M3 the DME relays what the rest of the car needs, including the 0x43F that the cluster shows the gear from. firmware

DirectionIdentifiers
SMG2 receives0x310, 0x311, 0x312, 0x313, 0x314, 0x515, 0x516, and 0x631 (diagnosis)
SMG2 sends0x410, 0x411, 0x412, and 0x200, 0x201, 0x630
The M3's DME sends on it0x310-0x314, 0x515 and its own 0x7xx messages. Never 0x516, in any MSS54 or MSS54HP release we have.

The SMG2 does not read anything else on this bus. 0x315, 0x316, 0x329, 0x545, 0x153, 0x1F0, 0x1F3, 0x1F5, 0x1F8 and 0x43F can neither cause nor fix a gearbox fault there. It keeps a buffer for 0x516 but nothing ever reads it.

Fault 128

Fault 128 has two sources. Both are checked only while the gearbox is in its running states and the engine turns above 250 rpm, which is why a car can sit at key-on forever without it and set it within a second of starting. firmware

Which messages have been seen

The freeze-frame value CAN-Empfangs-Sende-Fehler is not an error code. It is two bit masks, received since power-up in the high byte and sent in the low byte:

ByteBits 0-6
High, received0x310, 0x311, 0x312, 0x313, 0x314, 0x515, 0x516
Low, sent0x410, 0x411, 0x412

The received mask must be exactly 0x3F and the sent mask exactly 0x07, so a healthy unit reads 0x3F07. Sending 0x516 makes it 0x7F07 and sets fault 128. The bits are cleared only at power-up, so clearing faults does not help: the TCU has to go to sleep. field report confirms 0x3F07 and no fault at standstill and idle once 0x516 was dropped and the TCU power-cycled.

Alive counters and checksums

The freeze-frame value CAN-Botschaft-Fehler has bits 0-6 for a frozen alive counter and bits 8-14 for a wrong checksum, in the same message order as above. So 8 is 0x313's counter and 0x0400 would be 0x312's checksum.

Each check runs every 10 ms. A counter that has not changed for the number of cycles below, or one wrong checksum, sets the error.

MessageCounterUnchanged forChecksum
0x311byte 2 bits 4-77 cyclesbyte 7 = ~(b0 + (b1 & 3) + b3 + b4 + (b5 & 0x1F) + ctr)
0x312byte 0 bits 0-37 cyclesbyte 1 = ~(b2 + b3 + (b7 >> 4) + ctr)
0x313byte 0 bits 0-69 cyclesbyte 5 = ~(b1 + b2 + b6 + ctr)
0x314byte 1 bits 4-77 cyclesbyte 5 = ~(b0 + (b1 & 3) + b6 + (b7 & 0x0F) + ctr)

All sums are taken modulo 256. No such check exists for 0x310 or 0x515.

0x313 is only checked during a shift

The 0x313 check runs only while the SMG2's own torque intervention is active and its shift phase is 2 or 3. Both are on the bus: the intervention flag is 0x411 byte 2 bit 5, the phase is 0x411 byte 7 bits 0-3. A static 0x313 passes at standstill and sets fault 128 with CAN-Botschaft-Fehler = 8 about half a second into the first upshift. field report

A second monitor counts the inputs that are missing or failing. Two or more for about 100 ms set a separate fault, whose code we have not mapped.

What the engine computer sends

Field meanings from the SMG2's decoders and the M3 DME's own builders for the same frames. firmware

ByteMeaning

There is no acknowledgement in 0x313 and nothing to time out. For the check it is a counter and a checksum. The torque bytes affect how the shift feels.
