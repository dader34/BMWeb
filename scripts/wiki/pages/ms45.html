Hardware

A Motorola MPC555 with an external AMD Am29BL802CB, a 1 MB bottom-boot flash on a 16-bit bus. The program lives across both: part in the MPC555's internal flash (448 KB), the rest and the calibration in the external chip.

RAM is 26 KB, not 32

The MPC555's SRAM is 0x3F9800-0x3FFFFF: 10 KB from 0x3F9800 and 16 KB from 0x3FC000. The 6 KB below it, 0x3F8000-0x3F97FF, is reserved in the user's manual and does not exist on the chip. The DME agrees three ways: the loader clears RAM from 0x3F9800, its RAM self-test covers 0x6800 bytes from there, and its diagnostic address table lists RAM as 0x3F9800-0x3FFFFF. firmware

"Unused" RAM is not free on a running engine

About 1.5 KB of RAM is never written once the program is running, as far as the code shows. Filling it with a pattern on a car stalled the engine at idle and reset the DME right after start-up, with faults for the engine speed limiter reset, the throttle start-up check and air temperature plausibility. The start and firing paths read RAM that the boot leaves initialised. car

The external chip

Sector layout from the datasheet, which is also how the DME is partitioned. Offsets are into the chip. firmware

OffsetSizeHolds
0x0000016 + 8 + 8 + 96 KBBoot block and boot loader
0x20000128 KBMore boot loader code (about 230 functions up to 0x37E8C), blank from about 0x38800. Erasing it destroys the loader.
0x40000128 KBCalibration, 0x1D000 bytes of data, valid marks at the top
0x60000128 KBProgram
0x80000256 KBProgram
0xC0000256 KBProgram, valid marks at the top

The chip is single-bank. While it erases or programs, every read returns status, so no code can run from it. Anything that writes the chip from the running program has to execute from SRAM or internal flash with interrupts off. Erase Suspend is ignored in burst mode, which the DME turns on at boot, so the chip cannot be erased with the engine running. firmware

The programming session

This is the order of jobs in a whole-program flash, from a real flasher log. The emulated DME answers every step the same way. car emulator 

1A 89                          read serial number
31 07 03 <4 bytes>             read the seed
31 08 00 00 00 10 <key>        send the key       -> 71 08 01 accepted, 71 08 00 refused
10 85 05                       programming session, 115200 baud
83 03 00 78 18 F0 00           timing: P2max 3 s, P3min 12 ms
31 02 06 00 00 02 0A 00 00     erase the program: 0x02060000 + 0xA0000
34 .. 36 .. 37                 download the external program, 253-byte blocks
34 00 00 00 06 00 07 00 00     download the internal flash: 0x06000000 + 0x70000
31 02 04 00 00 02 02 00 00     erase the calibration: 0x02040000 + 0x20000
34 04 00 00 02 00 01 D0 00     download the calibration
10 81 01                       default session, 9600 baud (the loader keeps running)
31 09 02                       check the program signature -> 71 09 01
31 09 04                       check the data signature    -> 71 09 01
11 01                          reset
  • Addresses go as bytes 2, 1, 0, then 3. The external chip is 0x02000000 + offset and the internal flash 0x06000000 + offset. There is no separate erase for the internal flash: erasing the program region erases the external program sectors and all of the internal flash. emulator
  • The key answer is 71 08 01 for accepted. A positive answer 71 08 00 means the key was refused, so checking only for 71 passes a wrong key. car
  • The serial number used for the key is the last four bytes of the answer's payload, not of the telegram, which ends in a checksum. car
  • Reading needs no unlock. A calibration read works in the default 9600 baud session. car
  • The first erase hands over. The running program takes the first erase request, shuts itself down and jumps into the boot loader. That request is never answered; the next one is served by the loader. emulator

Baud rate is a parameter

The loader's 10 85 <code> takes codes 0-5 from a table: 2400, 9600, 19200, 38400, 57600, 115200. Any code of 6 or more is followed by a 24-bit baud rate, so 10 85 06 03 D0 90 asks for 250000, and the answer echoes it. The serial divider is round(1250000 / baud). The stock loader can therefore run any rate the line carries without a patch. emulator

A block answer is 76 <counter, 2 bytes> <status>, with status 01 for written and 02 for failed.

Blank blocks can be skipped

After an erase, downloading only the runs of bytes that are not FF leaves the chip identical to a full write. The signature check passes and the program starts. Runs may start at odd addresses and be a single block long. The stock calibration has 125 of 470 blocks blank at the end, the external program 535 of 2590. emulator

The loader does not clamp a download to the erased sector

A range that ran from the erased calibration across 0x5D000 into the unerased program was accepted and programmed into it. Programming only clears bits, so that corrupts the program. A tool that sends runs must clamp them to the region it erased. emulator

What makes a flash valid

The loader computes checksums in the background, ten bytes per pass, both CRC-32/MPEG-2. emulator

  • Program: over the internal flash and the external program, stored at 0x60000 and 0x60340.
  • Calibration: over 0x40200-0x5CFFF, with start, end and initial value from the header at 0x40104, stored at 0x40100. The running program re-checks the same range in the background.

31 09 then checks the references and an RSA signature over the MD5 of the listed segments. On success it writes marks into the last bytes of the sector. At reset the loader starts the program only when all four are there. emulator

A half-written program is recoverable: after an erase the DME stays in its boot loader and accepts a new program flash. car

The calibration definition

Checked by running the program and comparing every read it makes against the community XDF. emulator

  • Coverage is complete. All 4,325 single-value reads land on a defined constant with the right start and size, and every table the lookup routines are handed is defined.
  • One axis is missing: a 6-point 16-bit axis at calibration 0x8E30, used by the cruise control.
  • 320 items have no description, 264 constants and 56 tables.
  • One scaling looks wrong: c_temp_cur_on_ls_down is defined as 1/16 °C, but the variable it is compared with is 1/64 °C minus 33. Of 359 constants whose scale the code reveals, the other 354 agree.
